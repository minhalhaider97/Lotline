10. GSAP REACT SETUP REQUIREMENTS
---------------------------------

Import and register ScrollTrigger once in a client/browser entry:

  import { gsap } from "gsap";
  import { ScrollTrigger } from "gsap/ScrollTrigger";
  gsap.registerPlugin(ScrollTrigger);

Implementation rules:

- Create animations inside React effects or a reusable GSAP hook.
- Scope selectors with gsap.context() to the component ref.
- Revert the GSAP context during component cleanup.
- Kill component-owned ScrollTriggers and timers during cleanup.
- Refresh ScrollTrigger after fonts, important images, or lazy panels change
  layout.
- Use gsap.matchMedia() for desktop/mobile animation differences.
- Never create a new timeline on every render.
- Animate transform and opacity wherever possible.
- Avoid layout-heavy animation of top/left/width/height in continuous loops.
- Use will-change sparingly and remove it after expensive transitions.


11. LENIS SETUP REQUIREMENTS
----------------------------

Use Lenis for smooth scrolling only when reduced motion is not requested.
Synchronize it with GSAP ScrollTrigger:

- Create one Lenis instance at the app shell.
- Forward Lenis scroll events to ScrollTrigger.update.
- Drive Lenis from the GSAP ticker or use a single controlled requestAnimationFrame
  loop, never both.
- Disable GSAP lag smoothing only if required by the chosen integration and
  verified during testing.
- Stop Lenis while the mobile menu or modal dialog is open.
- Destroy Lenis and remove ticker callbacks during cleanup.
- Preserve native scrolling on touch devices when smoothing harms usability.
- Anchor links must account for the sticky header.
- Respect prefers-reduced-motion.


12. LOTTIE SETUP REQUIREMENTS
-----------------------------

Use @lottiefiles/dotlottie-react for original LotLine AI .lottie or JSON
assets. The older @lottiefiles/react-lottie-player package is deprecated and
must not be installed.

Rules:

- Store owned/exported files locally under src/assets/lottie or public/lottie.
- Do not hotlink Flai animations.
- Lazy-load below-the-fold players.
- Pause animations while off screen.
- Provide a static SVG/image fallback.
- Stop or simplify playback for reduced-motion users.
- Keep decorative animations aria-hidden.


13. FLAI-INSPIRED MOTION INVENTORY TO IMPLEMENT
------------------------------------------------

The following inventory is based on the public Flai website available on the
reference date. Recreate each applicable motion pattern with original LotLine
AI content and styling.

A. Page loader and first impression

- Branded loader/intro artwork.
- Loader exits through a short GSAP timeline.
- Hero animation begins while the loader clears.
- Safe immediate fallback if GSAP is unavailable.
- Loader must never block the page indefinitely.

B. Hero entrance

- Navigation items reveal in a controlled sequence.
- Eyebrow, headline, paragraph, and CTA reveal with staggered timing.
- Headline is split into words for a masked upward reveal.
- Hero media/artwork settles from scale/position/opacity.
- Small decorative elements float gently with varied duration.
- Background media/parallax responds subtly to scroll.

C. Hero conversation loop

- Chat turns appear one at a time.
- Existing messages move backward/up as a new message arrives.
- The outgoing turn receives a brief blur/fade.
- Timing adapts to message length.
- The loop resets without a visible jump.
- Mobile uses a simpler flow to avoid clipped content.
- The loop pauses or becomes static for reduced motion.

D. Smooth scrolling and navigation

- Lenis-driven smooth wheel scrolling on supported desktop browsers.
- ScrollTrigger remains synchronized.
- Sticky navigation changes visual state after the first scroll threshold.
- Anchor links glide to sections without hiding headings under the nav.
- Mobile menu stops background scrolling and restores it on close.
- Native scrolling remains the fallback if Lenis or GSAP fails.

E. Scroll reveals

- Section labels, headings, copy, cards, and media reveal as they enter.
- Use grouped composition reveals, not a distracting left-to-right cascade for
  every grid.
- Word/character reveals are reserved for major display statements.
- Reveal logic runs once unless repetition has a clear narrative purpose.

F. Parallax and decorative motion

- Background layers move at a slower rate than foreground content.
- Floating marks/cards use small, varied vertical movement.
- Movement stays within transform/opacity performance limits.
- Disable parallax on reduced motion and low-power/touch contexts if needed.

G. Animated feature tabs / dealership CRM preview

- Accessible tabs work even if GSAP fails.
- Active-tab progress hairline fills during its display interval.
- Tabs may auto-advance only while the section is visible.
- Hover/focus pauses auto-advance long enough to read.
- Each tab panel has an original entrance composition:
  - KPI cards stagger in.
  - Dashboard shell and icons appear in sequence.
  - Chat messages show typing dots before message content.
  - Tables reveal row by row.
  - Bars grow from their origin.
  - Sparkline/chart paths draw or wipe into view.
  - Numeric counters animate from zero to verified/illustrative values.
- Clicking the active/another tab cancels the old timeline cleanly.

H. Statement/story carousel

- Glass statement cards trade visual focus.
- Desktop may use a pinned, scrubbed horizontal/stacked sequence.
- Mobile presents one readable card at a time.
- Autoplay fallback pauses on hover/focus and while the page is hidden.
- Controls and content remain usable with GSAP disabled.

I. Character-fill statement

- One major product statement may fill/reveal character by character based on
  scroll progress.
- Do not pin the section if ordinary scrolling communicates the story better.
- Screen readers receive the unsplit sentence, not isolated characters.

J. Sales/use-case cards

- Cards enter as a balanced group.
- On pointer hover/focus, each card reveals its own relevant mini-composition.
- Chat snippets may animate typing/arrival.
- Touch devices show the content without requiring hover.

K. Integration orbit

- Concentric paths settle into place.
- Original LotLine AI integration/placeholder cards enter after the heading.
- Cards orbit elliptically on larger screens.
- Cards dim/blur subtly when crossing the headline zone if readability needs it.
- Mobile uses a wrapped or simplified orbital layout.
- Never display unverified integration logos or imply partnerships.

L. Dealer/customer wall replacement

- Do not copy Flai's dealership-logo wall.
- If LotLine AI later has authorized customer logos, cells can crossfade between
  approved marks while visible.
- Until then use truthful product/data-source concepts, or omit this animation.

M. Audio/listen experience

- Audio play/pause state is real and accessible.
- Waveform bars animate only during playback.
- Conversation bubbles appear in sync with audio timestamps.
- The conversation window reveals before playback begins.
- Audio pauses when off screen, when a modal takes focus, or when requested.
- Provide a complete transcript and keyboard-operable controls.
- Do not claim microphone capture when the implementation is only simulated.

N. Case-study/media rail

- Cards reveal when the section enters.
- Horizontal rail can loop continuously on desktop.
- Scroll velocity may influence rail speed/direction without making it hard to
  read.
- Touch users can drag/swipe.
- A drag must not accidentally activate the card.
- Cloned loop items are aria-hidden and removed from the tab order.
- Media opens in an accessible dialog.
- Opening the dialog pauses background movement/audio and locks scroll.
- Closing restores focus to the launching card.
- Use this only after real LotLine AI case studies exist.

O. Infinite marquees

- Continuous rows use enough cloned items to avoid visible gaps.
- Rows pause when outside the viewport.
- Speed can respond gently to scroll velocity.
- Clones are hidden from assistive technology.
- Reduced-motion mode displays a static wrapped grid.

P. Voice/demo interaction motion

- Idle, requesting permission, listening, thinking, speaking, interrupted,
  stopped, and error states have distinct visual feedback.
- Orb pulse and waveform represent real state, not fake activity.
- Mic-active state is always visible.
- Text status remains available for users who cannot perceive animation.
- Reduce/suppress continuous pulsing for reduced-motion users.

Q. Counters and charts

- Counters animate only when they enter the viewport.
- Use only verified values or label demo values as illustrative.
- Charts reveal through masks/scale/path drawing.
- Final values remain readable without JavaScript or animation.

R. FAQ and accordion motion

- Height/opacity transition with no content clipping after resize.
- Correct aria-expanded and aria-controls state.
- Keyboard operation works without animation.
- Reduced-motion mode opens/closes immediately.

S. Modal and form motion

- Backdrop fades in and dialog enters subtly.
- Focus moves into the dialog and is trapped.
- Escape/backdrop/close button behavior is defined.
- Background Lenis/animations/audio pause while open.
- Exit finishes before unmount, unless reduced motion is active.
- Focus returns to the trigger.

T. Footer artwork

- Optional original LotLine AI wordmark/artwork parallax.
- Subtle moving highlight/glint may cross the artwork.
- Decorative video/Lottie gauge plays once when visible.
- Static fallback for reduced motion and failed media.


14. REDUCED-MOTION AND FALLBACK REQUIREMENTS
--------------------------------------------

All motion is progressive enhancement.

Required behavior when prefers-reduced-motion: reduce is active:

- Do not initialize Lenis smoothing.
- Do not run parallax, marquee, orbit, looping chat, or continuous glint.
- Replace word/character stagger with immediate visible text.
- Replace large movement with short opacity changes or no transition.
- Keep tabs, accordions, dialogs, audio controls, and navigation fully usable.
- Show the final state of counters and charts.
- Do not autoplay audio or video.

Required behavior if GSAP/ScrollTrigger fails to load:

- All content remains visible.
- Navigation and anchors work natively.
- Tabs and accordions work through React state.
- No loader traps the visitor.
- No element remains at opacity: 0 because animation initialization failed.


15. PERFORMANCE REQUIREMENTS FOR MOTION
---------------------------------------

- Lazy-load GSAP-heavy below-the-fold sections where practical.
- Lazy-load dotLottie and media assets.
- Pause timelines, tickers, waveforms, and marquees when off screen.
- Pause nonessential work when document.visibilityState is hidden.
- Prefer transform and opacity.
- Limit simultaneous backdrop-filter and blur animation.
- Avoid animating large fixed blurred layers on low-power mobile devices.
- Clean up every event listener, timer, animation frame, timeline, and
  ScrollTrigger on unmount.
- Test at 390 px, 768 px, and 1440 px.
- Test Chrome/Edge, Firefox, iOS Safari, and Android Chrome.
- Maintain the Core Web Vitals targets in 02_WEBSITE_IMPLEMENTATION_SPEC.md.
